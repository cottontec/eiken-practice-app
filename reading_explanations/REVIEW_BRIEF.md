# Reading解説 点検担当（粗探し役）への指示書

あなたは、別の担当が書いた解説を、原画像と突き合わせて点検し、直す担当です。担当は依頼文で指定されたバッチだけです。
`AGENT_BRIEF.md`（同じフォルダ）と `$SRC/00_ClaudeCodeへの依頼文.md` を先に読み、ファイル形式と文章の約束を把握してください。git操作はしません。

## 手順

1. `$SRC/batches/<batchId>.source.json` と画像（`$SRC/` + images[].key）を開く。抽出テキストがあっても画像を正とする。
2. `$WORK/_writer_notes.md`（作成担当の申し送り。特に「要確認」）を読み、そこに挙がった点は重点的に確かめる。そのうえで `$WORK/` の各 `<questionId>.txt` と `<unitId>.passage.txt` を、1問ずつ次の観点で点検する。
   - 正解の一意性：自分でも解き、正解が1つに決まるか。他の選択肢が確実に誤りといえる根拠が書かれているか。
   - choices / answerText / order が画像どおりか（つづり・語の抜け）。
   - 本文全訳：全文が訳されているか（文の抜け・段落の抜け）、否定・比較・条件・時制・主語・数量の誤訳がないか。大問2の空所表示が正しいか。
   - 設問・全選択肢の訳が正確か。
   - 【考え方】が実際の英文を引用し、根拠から答えへ筋道が通っているか。言い換えの対応が正しいか。
   - 【ほかの選択肢】の理由が本文に即しているか（推測による否定・誤った決めつけがないか）。
   - 小学校高学年に通じるか：難しい語・文法用語に（）の説明があるか。長すぎる一文がないか。幼すぎる口調でないか。
   - 定型文の使い回しになっていないか。
3. 問題があればファイルを直接直す。直せない疑問（正式解答への疑問、画像の判読不能）は、ヘッダを `status: issue` と `issueReason:` にして本文を空にする。
4. 点検を終えた問題ファイルのヘッダに `reviewed: yes` を加える（直した場合も、問題がなかった場合も）。passageファイルにはヘッダを付けない。
5. `$WORK/_review.md` に次の2つの見出しで書く（見出しの文字は変えない。取りまとめ時に機械的に抜き出す）。
   - `## 修正一覧`：1行1件、`- <問題ID>：<直した内容>（重大/軽微）`
   - `## 要確認`：1行1件、`- <問題ID>：<人の目で確認が要る点>`。なければ `- なし`
6. 次を実行し ERROR 0 を確認する。
   ```
   python3 -I /home/user/eiken-practice-app/reading_explanations/tools/build_and_check.py --src-root /tmp/claude-0/-home-user-eiken-practice-app/37990840-d70a-5962-afc7-2daeb13275d4/scratchpad/zips --part <分割番号> --batch <batchId>
   ```

## 報告（取りまとめ役へ）

点検数・修正件数（重大＝正解根拠や訳の誤り／軽微＝表現）・疑義件数・要確認の一覧を簡潔に。
「問題なし」と書くのは、実際に画像と照合した問題だけにする。
